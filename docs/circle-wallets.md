# Circle Programmable Wallets — arcmeter Integration

## Why Circle Wallets?

Each AI model seller and each buyer agent in arcmeter's marketplace needs a
non-custodial on-chain wallet to send and receive USDC payments. Circle's
**Programmable Wallets** (developer-controlled) give us:

- Instant wallet provisioning via REST API — no seed phrases, no user interaction
- Built-in USDC support on multiple testnets (Polygon Amoy, Ethereum Sepolia, etc.)
- Transfer API to settle earnings from a seller wallet to any external address
- A single API key controls all wallets in an entity, ideal for hackathon PoC

**Blockchain choice:** Circle does not yet support "ARC-TESTNET" natively. We use
`MATIC-AMOY` (Polygon Amoy testnet), which Circle fully supports and is functionally
equivalent for this demo. When Circle adds Arc mainnet support, change
`DEFAULT_BLOCKCHAIN` in `api/circle.js`.

---

## Getting API Keys

1. Sign up at <https://console.circle.com>
2. Create a new project → choose **Programmable Wallets**
3. Copy your **API Key** from the project settings
4. Generate an **Entity Secret** (Circle's UI walks you through this) — it is used
   to authorize developer-controlled wallet operations
5. After running `setup-wallets.js`, copy the printed `walletSetId` into
   `CIRCLE_WALLET_SET_ID`

Set these three environment variables before starting the server:

```bash
export CIRCLE_API_KEY=your-api-key-here
export CIRCLE_ENTITY_SECRET=your-entity-secret-here
export CIRCLE_WALLET_SET_ID=your-wallet-set-id-here   # optional; setup script creates one
```

---

## Running Setup

```bash
# From the arcmeter directory:
node scripts/setup-wallets.js
```

This will:
1. Create one **WalletSet** (`arcmeter-hackathon`)
2. Create three **seller wallets** — one per model (`gemini-flash`, `llama-local`, `nl2shell`)
3. Create one **buyer/agent wallet**
4. Write `arcmeter/wallets.json` with all IDs and addresses

## Mock Mode

If `CIRCLE_API_KEY` is not set, every function in `api/circle.js` runs in **mock
mode**:

- Wallet IDs and addresses are randomly generated fakes (stable within one process)
- All API calls are skipped; no network requests are made
- A `[circle:mock]` log line is printed for each operation
- `wallets.json` is still written so downstream modules work

```bash
# Demo without any Circle credentials:
node scripts/setup-wallets.js
# → prints mock wallet IDs / addresses
# → writes wallets.json (mock: true)
```

The Express routes in `wallet-routes.js` also fall back to mock mode automatically.

## API Routes (wallet-routes.js)

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/wallets` | Create a wallet `{name, role: "seller"\|"buyer"}` |
| `GET`  | `/v1/wallets` | List all created wallets |
| `GET`  | `/v1/wallets/:id/balance` | USDC balance for a wallet |
| `POST` | `/v1/wallets/:id/payout` | Transfer USDC to external address `{to, amount}` |

---

## Sample curl Commands

```bash
BASE=http://localhost:7402

# Create a seller wallet
curl -s -X POST $BASE/v1/wallets \
  -H "Content-Type: application/json" \
  -d '{"name":"seller-gemini-flash","role":"seller"}' | jq .

# List wallets
curl -s $BASE/v1/wallets | jq .

# Check balance
curl -s $BASE/v1/wallets/<walletId>/balance | jq .

# Payout (settle earnings to external address)
curl -s -X POST $BASE/v1/wallets/<walletId>/payout \
  -H "Content-Type: application/json" \
  -d '{"to":"0xYourExternalAddress","amount":"1.00"}' | jq .
```

## Files

| File | Purpose |
|------|---------|
| `api/circle.js` | Circle API wrapper with mock fallback |
| `api/wallet-routes.js` | Express router, mounts on `/` |
| `scripts/setup-wallets.js` | One-time wallet provisioning script |
| `wallets.json` | Generated by setup script; read by other modules |
| `wallets.jsonl` | Append-only log of wallets created via the API routes |
